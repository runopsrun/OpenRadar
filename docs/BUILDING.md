# Building and releasing

How to produce a production frontend, a native binary, and platform installers,
and how to prepare a release. For toolchain installation, see
[Getting started](GETTING_STARTED.md).

---

## 1. Build pipeline

`npm run tauri:build` runs three stages:

```text
tsc → vite build → cargo build --release → tauri bundle
```

1. **`tsc`** type-checks the frontend (`npm run build` runs `tsc && vite build`).
2. **`vite build`** writes the production frontend to `dist/` (ES2021 target,
   minified unless `TAURI_ENV_DEBUG` is set).
3. **Tauri** compiles the Rust shell in release mode, embeds `dist/`, and creates
   the configured bundles.

`beforeBuildCommand` in `src-tauri/tauri.conf.json` is `npm run build`, so
running the Tauri CLI directly also rebuilds the frontend.

## 3. Standard builds

### Frontend only

```bash
npm run build
```

Output: `dist/`. Serve it with any static host. There is no server-side
component, but the browser build needs network access to the selected data
source and basemaps.

### Native binary, no installers

```bash
npx tauri build --no-bundle
```

Output:

```text
src-tauri/target/release/openradar
```

This is the fastest way to verify the Rust shell and embedded frontend. The
binary is self-contained apart from the system webview and normal shared
libraries.

### Installers

```bash
npm run tauri:build
```

Or select bundle formats:

```bash
npx tauri build --bundles deb
npx tauri build --bundles appimage
npx tauri build --bundles rpm
npx tauri build --bundles deb,appimage
```

On Windows:

```powershell
npx tauri build --bundles msi
npx tauri build --bundles nsis
```

On macOS:

```bash
npx tauri build --bundles app,dmg
```

`bundle.targets` is `"all"` in `tauri.conf.json`, so a full `tauri build` emits
every format supported by the host.

## 4. Release profile

From `src-tauri/Cargo.toml`:

```toml
[profile.release]
codegen-units = 1
lto = true
opt-level = 3
panic = "abort"
strip = true
```

These settings favour size and runtime speed over compile time. A full release
build can take several minutes on a first run because all Rust dependencies must
be compiled with LTO.

Reference sizes observed for v0.1.0 on Linux x86_64:

| Artifact | Approximate size |
| --- | --- |
| `openradar` binary | ~6.5 MB |
| `.deb` | ~2.9 MB |

Sizes vary with compiler version, linker, and bundled assets.

## 6. Icons

Source icon: `app-icon.svg` at the repository root. Generated platform assets
live in `src-tauri/icons/` (PNG sizes, `.ico`, `.icns`, Android/iOS sets).

Regenerate after changing the source:

```bash
npx tauri icon app-icon.svg
```

Then rebuild. The bundle configuration references:

```json
[
  "icons/32x32.png",
  "icons/128x128.png",
  "icons/128x128@2x.png",
  "icons/icon.icns",
  "icons/icon.ico"
]
```

Keep those files present or the bundle step fails.

## 7. Versioning

The version appears in several places. Update all of them together:

| File | Field |
| --- | --- |
| `package.json` | `"version"` |
| `src-tauri/Cargo.toml` | `[package] version` |
| `src-tauri/tauri.conf.json` | `"version"` |
| `src/config/constants.ts` | `APP_VERSION` |
| `src-tauri/Cargo.lock` | Regenerated by `cargo check` / build |

The Settings panel reads `APP_VERSION`; the About dialog uses the same constant,
and Tauri uses `tauri.conf.json` for installer metadata. Mismatched values
produce confusing installers and UI labels.

After bumping:

```bash
npm run typecheck
cargo check --manifest-path src-tauri/Cargo.toml
npx tauri build --no-bundle
```

Update [Changelog](CHANGELOG.md) and the version noted in
[docs/README.md](README.md).

## 8. Tauri configuration that affects builds

From `src-tauri/tauri.conf.json`:

| Setting | Value | Effect |
| --- | --- | --- |
| `productName` | `OpenRadar` | Installer and app name. |
| `identifier` | `com.mumma.openradar` | Config directory, bundle ID, macOS identity. Changing it moves the settings path. |
| `build.devUrl` | `http://localhost:1420` | Must match Vite's strict port. |
| `build.frontendDist` | `../dist` | Embedded frontend. |
| `app.windows[0]` | 1280×820, min 760×560 | Default and minimum size. |
| `app.security.csp` | see below | Network and asset policy. |
| `bundle.targets` | `"all"` | Every host-supported format. |
| `bundle.category` | `Weather` | Platform metadata. |

CSP summary: scripts only from the app; styles allow inline; images allow
`data:`, `blob:`, HTTPS, and HTTP; connections allow `ipc:`, HTTP(S), and
WebSocket; workers allow `blob:`; objects and frames are disabled. If you add a
new resource type, update the CSP deliberately rather than loosening
`default-src`.

`devCsp` is `null`, so development is not constrained by the production CSP.

## 9. Code signing and notarisation

### Windows

Unsigned MSI/NSIS installers trigger SmartScreen warnings. For distribution,
sign with a code-signing certificate and configure Tauri's Windows signing
settings (certificate path/thumbprint, timestamp URL, digest algorithm).
Sign the installer and the executable.

### macOS

Unsigned `.app`/`.dmg` bundles are blocked by Gatekeeper on other machines.
Distribution requires:

1. An Apple Developer ID certificate.
2. Code signing with hardened runtime.
3. Notarisation and stapling.

Configure Tauri's macOS signing identity and notarisation credentials in the
environment/CI. This release has not been validated on macOS; treat macOS
packaging as untested.

### Linux

`.deb` and `.rpm` packages are unsigned by default. AppImage is portable but
also unsigned. Publishing checksums (SHA-256) alongside artifacts is the minimum
integrity measure. Repository signing (APT/RPM) is a distribution choice, not
something the app config does.

## 10. Release checklist

### Before tagging

- [ ] `npm run typecheck` passes.
- [ ] `npm run build` passes.
- [ ] `cargo check --manifest-path src-tauri/Cargo.toml` passes.
- [ ] `cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings` is clean
      (or the remaining warnings are documented).
- [ ] `npx tauri build --no-bundle` produces a binary that launches.
- [ ] Target bundle formats build on their native hosts.
- [ ] Version numbers match in all four files.
- [ ] `Cargo.lock` and `package-lock.json` are committed.
- [ ] `LICENSE` and dependency notices are present.
- [ ] [Changelog](CHANGELOG.md) is updated.
- [ ] Docs affected by the release are updated.
- [ ] No secrets, local paths, or debug logging are committed.
- [ ] `dist/` and `src-tauri/target/` are not committed.

### Smoke test the artifact

Install or run the built artifact, not just the dev server:

1. Launch and wait for **Live**.
2. Play, pause, step, scrub, toggle loop and nowcast.
3. Switch each base map; overlays must reappear.
4. Toggle satellite, alerts, and each LibreWXR extra.
5. Search for a place and confirm the marker.
6. Toggle the theme, reload, confirm persistence.
7. Export a PNG and open the file.
8. Test the tray menu (Show, Refresh, Quit).
9. Resize to the minimum window size and check for clipped controls.
10. Disconnect the network and confirm stale/error handling is graceful.

### Publish

- [ ] Tag the release with the version.
- [ ] Upload installers and checksums.
- [ ] Include release notes and known limitations.
- [ ] Note the data-source terms and the “not for life-safety” warning.
- [ ] Keep the previous release available for rollback.

## 11. CI sketch

A minimal matrix can build on Linux and Windows:

```yaml
# Illustrative only; adapt to your CI provider.
jobs:
  build:
    strategy:
      matrix:
        os: [ubuntu-22.04, windows-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - uses: dtolnay/rust-toolchain@stable
      - run: npm ci
      - run: npm run typecheck
      - run: npm run build
      - run: cargo check --manifest-path src-tauri/Cargo.toml
      - run: npx tauri build
```

Linux runners need the WebKitGTK/AppIndicator packages installed first. Do not
build Linux bundles on Windows or vice versa; Tauri bundles are host-native.
Cross-compilation is possible for some targets but requires a custom toolchain
and sysroot, and is out of scope for this release.

## 12. Reproducibility and offline builds

- `npm ci` installs exactly `package-lock.json`.
- `cargo build --locked` uses `Cargo.lock` without updating it.
- The first build needs network access for npm and crates.io. Later builds can
  run offline if the caches are present.
- The app itself always needs network access at runtime for weather data and
  basemaps. There is no offline map or bundled radar archive.

## 13. Common build failures

| Symptom | Fix |
| --- | --- |
| `failed to run 'cargo metadata'` | `source "$HOME/.cargo/env"` or add `$HOME/.cargo/bin` to `PATH`. |
| `webkit2gtk-4.1` not found | Install the dev package for your distribution. |
| `patchelf` missing during AppImage | Install `patchelf`. |
| `rpmbuild` missing | Install `rpm-build` (Fedora) or `rpm` tooling. |
| Icon missing | Regenerate with `npx tauri icon app-icon.svg`. |
| TypeScript error after upgrade | Check strict-mode changes and `noUncheckedIndexedAccess`. |
| Linker out of memory during LTO | Close other builds, reduce jobs, or build on a machine with more RAM. |
| Bundle succeeds, app shows a blank window | Check CSP and the webview console; verify `dist/` was rebuilt. |

More runtime issues are covered in [Troubleshooting](TROUBLESHOOTING.md).
